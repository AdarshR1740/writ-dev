# Writ in Claude: what each tool does

Version 0.2.0. **Generated** from the MCP server by `npm run docs:update`: do not edit this file. To change a description, edit `src/tool-docs.ts`.

Writ's tools let Claude read your pieces and save work into Writ, on your own Claude subscription. You approve every step that changes the piece's direction; what Claude saves stays editable in Writ.

## Look things up

### `writ_list_pieces`

Lists your pieces with their code, title and stage, most recently updated first.

- **Used:** At the start of a chat, or when you name a piece.
- **Effect:** Only reads. Changes nothing.

| Parameter | Type | Required | What it is |
|---|---|---|---|
| `stage` | one of "contract", "research", "outline", "writing", "done" | no | Only pieces at this stage |
| `limit` | whole number | no |  |

### `writ_get_piece`

A piece's brief, its scope, and its outline with each section's id, level, status and word count.

- **Used:** Before working on a piece, and after changing it, to see where it stands.
- **Effect:** Only reads. Changes nothing.

| Parameter | Type | Required | What it is |
|---|---|---|---|
| `piece` | string | yes | The piece code (SI-0012) or id |

### `writ_get_section`

Everything needed to write one section: its purpose, the outline around it, the talking points with evidence, the approved research with links, and the current text.

- **Used:** Before drafting or checking a section.
- **Effect:** Only reads. Changes nothing.

| Parameter | Type | Required | What it is |
|---|---|---|---|
| `section_id` | string | yes | The section id |

### `writ_get_voice`

How the company writes: core voice, the format's style profile, audience, positioning and the rules learned from past edits.

- **Used:** Before drafting, so the text sounds like the company.
- **Effect:** Only reads. Changes nothing.

| Parameter | Type | Required | What it is |
|---|---|---|---|
| `piece` | string | yes | The piece code (SI-0012) or id |

### `writ_get_setup`

Where you stand: your companies, their formats, how much of the house file is filled in, and how many pieces each has.

- **Used:** At the start of onboarding or a new piece.
- **Effect:** Only reads. Changes nothing.

### `writ_get_context_documents`

The text of the house-file documents: ideal customer, core voice, positioning and strategy notes.

- **Used:** To read or improve the house file.
- **Effect:** Only reads. Changes nothing.

| Parameter | Type | Required | What it is |
|---|---|---|---|
| `company` | string | no | Company name or id, needed only when the writer belongs to more than one |

### `writ_get_research`

A piece's (or one section's) research items with their status, sources and whether the quote was checked.

- **Used:** When reviewing or reusing research.
- **Effect:** Only reads. Changes nothing.

| Parameter | Type | Required | What it is |
|---|---|---|---|
| `piece` | string | yes | The piece code (SI-0012) or id |
| `section_id` | string | no | Give it to list that section's own research |

### `writ_get_check_input`

Everything one check needs, numbered the way the save tools expect: the gap analysis, the outline's SEO/GEO check, a section's checks, or the final checks.

- **Used:** Right before running a check.
- **Effect:** Only reads. Changes nothing.

| Parameter | Type | Required | What it is |
|---|---|---|---|
| `piece` | string | yes | The piece code (SI-0012) or id |
| `scope` | one of "analysis", "outline", "section", "piece" | yes |  |
| `section_id` | string | no | Needed for scope section |

### `writ_check_piece`

A health check: what you will see on each step of the piece in Writ right now, and anything that looks wrong or stuck.

- **Used:** After saving an outline, reopening something or finishing a step. Claude tells you about every problem it reports.
- **Effect:** Only reads. Changes nothing.

| Parameter | Type | Required | What it is |
|---|---|---|---|
| `piece` | string | yes | The piece code (SI-0012) or id |

## Set up the company

### `writ_create_company`

Creates your company in Writ and makes you its editor. A company can't be deleted from here, so the name is confirmed first.

- **Used:** During onboarding, after you approve the name.
- **Effect:** Creates something new. Needs your go-ahead first.

| Parameter | Type | Required | What it is |
|---|---|---|---|
| `name` | string | yes | The company name, 2 to 120 characters |

### `writ_add_formats`

Switches on Writ's standard formats (blog, LinkedIn, case study, carousels, scripts, newsletter and more). Formats you already have are skipped.

- **Used:** During onboarding, with the company.
- **Effect:** Saves data you can still edit in Writ. Needs your go-ahead first.

| Parameter | Type | Required | What it is |
|---|---|---|---|
| `company` | string | no | Company name or id, needed only when the writer belongs to more than one |
| `templates` | list of string | no | Template keys or names to add; leave out for all of them |

### `writ_save_context_document`

Saves one house-file document (ideal customer, core voice, positioning, strategy notes). It will not replace existing text unless you agreed.

- **Used:** When you approve a house-file document drafted in chat.
- **Effect:** Saves data you can still edit in Writ. Needs your go-ahead first.

| Parameter | Type | Required | What it is |
|---|---|---|---|
| `kind` | one of "icp", "core_voice", "positioning", "strategy_notes" | yes |  |
| `content` | string | yes | The document as Markdown |
| `company` | string | no | Company name or id, needed only when the writer belongs to more than one |
| `replace` | boolean | no | True only after the writer agreed to replace the existing text |

## Start a piece and its scope

### `writ_start_piece`

Creates a new piece from the brief; Writ assigns its code.

- **Used:** After you confirm the brief.
- **Effect:** Creates something new. Needs your go-ahead first.

| Parameter | Type | Required | What it is |
|---|---|---|---|
| `title` | string | yes | The piece title, 1 to 200 characters |
| `topic` | string | yes | What the piece is about |
| `keyword` | string | no | The primary keyword |
| `goal` | string | no | What the piece should achieve |
| `audience` | string | no | Who it is for, if different from the company's usual reader |
| `format` | string | no | A format name or id from writ_get_setup |
| `company` | string | no | Company name or id, needed only when the writer belongs to more than one |
| `timing` | one of "just_in_time", "up_front" | no | Leave out to use the format's default |
| `customer` | string | no | The customer, for formats that ask for one (see brief_asks_for in writ_get_setup) |
| `approval_contact` | string | no | Who approves the piece at the customer, for formats that ask for it |
| `offer` | string | no | The offer, for formats that ask for one |
| `cta` | string | no | The call to action, for formats that ask for one |

### `writ_save_scope`

Saves the scope draft: the one question the piece answers and the points it should include. Works only while the scope step is open.

- **Used:** When you have agreed the scope in chat.
- **Effect:** Saves data you can still edit in Writ.

| Parameter | Type | Required | What it is |
|---|---|---|---|
| `piece` | string | yes | The piece code (SI-0012) or id |
| `core_question` | string | yes | One question, one sentence |
| `points` | list of string | yes | The full list of points, one short line each (at most 7, or 2 for a short format) |

### `writ_confirm_scope`

Confirms the scope, which moves the piece on to research.

- **Used:** Only after you approve the scope.
- **Effect:** Ends a step and moves the piece on. Needs your go-ahead first.

| Parameter | Type | Required | What it is |
|---|---|---|---|
| `piece` | string | yes | The piece code (SI-0012) or id |

## Research

### `writ_add_research`

Saves findings Claude found as unreviewed research items with their sources. Quotes are not checked against the pages.

- **Used:** After searching the web for the piece or for one section.
- **Effect:** Saves data you can still edit in Writ.

| Parameter | Type | Required | What it is |
|---|---|---|---|
| `piece` | string | yes | The piece code (SI-0012) or id |
| `findings` | list of { url: string, title?: string, statement: string, quote?: string, source_type: one of "original_research", "official", "practitioner", "critical", "data", "web", "serp", secondary?: boolean, published?: string } | yes | 1 to 20 findings |
| `section_id` | string | no | Add the findings to this section's research instead of the piece's |
| `auto` | boolean | no | True when preparing a section whose brief step is open |
| `gap` | string | no | The gap this search is aimed at (gap-0, gap-1), for research that answers a gap found by the gap analysis; allowed while the outline is open |

### `writ_review_research`

| Parameter | Type | Required | What it is |
|---|---|---|---|
| `decisions` | list of { item: string, decision: one of "approved", "rejected", "unreviewed", statement?: string } | yes |  |

### `writ_complete_research`

Finishes the research step, which moves the piece on to the outline.

- **Used:** Only after you approve.
- **Effect:** Ends a step and moves the piece on. Needs your go-ahead first.

| Parameter | Type | Required | What it is |
|---|---|---|---|
| `piece` | string | yes | The piece code (SI-0012) or id |

## Gap analysis (benchmark)

### `writ_save_analysis`

Saves the gap analysis: whether the scope and research still match the topic, the gaps, and suggestions for the scope.

- **Used:** After Claude runs the analysis.
- **Effect:** Saves data you can still edit in Writ.

| Parameter | Type | Required | What it is |
|---|---|---|---|
| `piece` | string | yes | The piece code (SI-0012) or id |
| `verdict` | one of "aligned", "partly", "drifted" | yes |  |
| `summary` | string | yes | One or two sentences |
| `drift` | list of { text: string, items?: list of whole number, points?: list of whole number } | no | What has moved away from the topic, by theme; items are research numbers, points are scope point numbers |
| `gaps` | list of { text: string, expert_question: string, points?: list of whole number } | no |  |
| `contract_suggestions` | list of { change: string, why: string } | no | Suggested changes to the scope; the writer decides |

### `writ_mark_findings`

Records your decisions on the analysis findings: ignored, resolved or open again.

- **Used:** When you go through the findings.
- **Effect:** Saves data you can still edit in Writ. Needs your go-ahead first.

| Parameter | Type | Required | What it is |
|---|---|---|---|
| `piece` | string | yes | The piece code (SI-0012) or id |
| `marks` | list of { finding: string, state: one of "ignored", "resolved", "open" } | yes |  |

### `writ_apply_alignment_fixes`

Applies the fixes you chose: reject research, edit, remove or add scope points, and add sections. Works only while the outline is open, and Writ can undo the fixes afterwards.

- **Used:** After you pick which fixes to apply.
- **Effect:** Saves data you can still edit in Writ. Needs your go-ahead first.

| Parameter | Type | Required | What it is |
|---|---|---|---|
| `piece` | string | yes | The piece code (SI-0012) or id |
| `fixes` | { reject_items?: list of whole number, edit_points?: list of { point: whole number, text: string }, remove_points?: list of whole number, add_points?: list of string, add_sections?: list of { heading: string, purpose?: string, covers?: list of whole number } } | yes |  |
| `resolves` | list of string | no | Findings these fixes close (gap-0, drift-1, suggestion-0) |

### `writ_add_expert_answer`

Saves your own answer to a gap's expert question as an insight card and approved research.

- **Used:** When you answer a question only you can answer.
- **Effect:** Saves data you can still edit in Writ. Needs your go-ahead first.

| Parameter | Type | Required | What it is |

Saves a section's talking points, then has Writ finish the section's research step and confirm its brief. That moves the section to writing, so it is ready to draft.

- **Used:** When the points for a section are agreed.
- **Effect:** Saves data you can still edit in Writ.

| Parameter | Type | Required | What it is |
|---|---|---|---|
| `section_id` | string | yes | The section id from writ_get_piece |
| `points` | list of { point: string, direction?: string, evidence?: string, refs?: list of whole number, sub_section?: string } | yes | 1 to 12 points, usually 4 to 10 |

### `writ_save_section_draft`

Saves a drafted section as an AI draft for you to review in Writ. It becomes the section's text only if you have written none (or the text is still exactly the previous AI draft, untouched), and never overwrites text you wrote.

- **Used:** After Claude drafts a section.
- **Effect:** Saves data you can still edit in Writ.

| Parameter | Type | Required | What it is |
|---|---|---|---|
| `section_id` | string | yes |  |
| `text` | string | yes | The section text as Markdown |

### `writ_save_section_checks`

Saves a section's grammar, fact and scope check results, stamped with the text version they were run on.

- **Used:** After Claude checks a section.
- **Effect:** Saves data you can still edit in Writ.

| Parameter | Type | Required | What it is |
|---|---|---|---|
| `section_id` | string | yes | The section id |
| `content_rev` | whole number | yes | The content_rev from writ_get_check_input |
| `grammar` | { suggestions: list of { original: string, replacement: string, reason?: string } } | no |  |
| `fact` | { flags: list of { sentence: string, kind: one of "unsupported", "mismatch", issue: string, item?: whole number } } | no | item is the research number for a mismatch; leave it out or use 0 for unsupported |
| `contract` | { results: list of { expectation: whole number, status: one of "met", "partly", "missing", evidence?: string, gap?: string } } | no |  |

## Prompts

Start these from Claude by typing the command.

### `/writ:onboarding`

A guide to what you can do with Writ in Claude, then a walk through creating your company and building your house file.

Start here if you're new. It checks where you stand and takes you through what is left, saving each document only when you approve it.

### `/writ:new_piece`

Takes a piece from idea to a first draft: the brief, scope, research, outline, then each section's talking points and draft.

Claude asks for your feedback at every step and only confirms a step when you approve. There is no sign-off in chat: the draft stays in Writ for your review.

- `idea` (optional): Your idea for the piece, in a few words

### `/writ:write_section`

Drafts one prepared section from its talking points and approved research, in the company's voice, and saves it to Writ.

Give it the piece code and the section id. It follows Writ's drafting rules: approved research only, sources linked in line, headings that organise the section.

- `section_id`: The section id from writ_get_piece
- `piece`: The piece code, for example SI-0012
